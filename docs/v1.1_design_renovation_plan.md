# PlantyLink v1.1 — Plan de Renovación de Diseño

## Visión

Transformar PlantyLink de una app funcional a una experiencia premium con micro-interacciones,
transiciones fluidas, y un lenguaje visual cálido inspirado en las referencias (paleta verde/naranja/crema,
cards con sombras suaves, segmented controls animados, tipografía con jerarquía clara).

---

## Fase 1: Sistema de Diseño Expandido (Fundamentos)

### 1.1 — Tokens de diseño (`lib/core/theme/app_tokens.dart`)
Crear archivo de constantes centralizadas para reemplazar valores hard-coded.

```
Spacing: xs(4), sm(8), md(16), lg(24), xl(32), xxl(48)
Radius:  sm(8), md(12), lg(16), xl(20), xxl(24), pill(999)
Shadow:  subtle(blur:4, y:2), medium(blur:12, y:4), elevated(blur:24, y:8)
Duration: micro(100ms), fast(200ms), normal(300ms), slow(500ms), entrance(800ms)
Curve:   snappy(easeOutCubic), smooth(easeInOut), bounce(elasticOut)
```

### 1.2 — Warm palette refinement (`app_colors.dart`)
Ajustar la paleta para ser más cálida, inspirada en las referencias:

**Light mode:**
- Background: `#FAFAF5` (crema cálido) en vez de `#F0FDF4` (verde pálido)
- Card background: `#FFFFFF` (se mantiene)
- Card border: `#E8E5DC` (beige suave) en vez de `#BBF7D0`
- Accent secundario: `#F97316` (naranja cálido) para CTAs de acción
- Surface variant: `#F5F0E8` (arena) para backgrounds de secciones

**Dark mode:**
- Añadir un tono `warmGray` sutil al background: `#0C0F0E` en vez de `#07110E`
- Card borders más visibles: `#243830`

### 1.3 — Tipografía monoespaciada para sensores
- Sensor values: `GoogleFonts.jetBrainsMono` o `GoogleFonts.spaceGrotesk`
- Solo para números en `SensorCard`, `SimpleMetric`, `CircularMetric`, dashboard header
- Labels y textos siguen con `PlusJakartaSans`

## Fase 2: Micro-interacciones (Widget por Widget)

### 2.1 — Animated Cards con entrada escalonada

**Nuevo widget: `AnimatedAppCard`**
- Reemplaza al `AppCard` estático
- Entrada con `FadeTransition` + `SlideTransition` (desde abajo, 0.05 offset)
- Parámetro `delay` para stagger effect (cada card entra 80ms después)
- Hover/press: escala sutil a 0.98 + sombra elevada (via `AnimatedScale` + `AnimatedContainer`)

**Aplicar en:**
- Dashboard: sensor cards, pump grid, alert cards
- Settings: navigation tiles
- History: chart cards

### 2.2 — Pull-to-refresh con feedback háptico

**Dashboard y History:**
- `RefreshIndicator` con color `primary`
- Vibración leve al activar el refresh
- Icono de refresh que rota suavemente

### 2.3 — Sensor value transitions

**Nuevo widget: `AnimatedValue`**
- Cuando el valor numérico cambia, animar con `TweenAnimationBuilder<double>`
- Interpolación numérica suave (300ms)
- Flash de color sutil (verde = subió, rojo = bajó) que se desvanece
- Aplicar en `SensorCard`, `SimpleMetric`, `CircularMetric`

### 2.4 — Pump buttons mejorados (`IlluminatedButton` v2)

Evolucionar el toggle actual:
- Al activar: ripple circular verde que se expande desde el centro
- Icono hace scale up → rotate sutil (10°) → scale normal
- Glow pulsante mientras la bomba está activa (via `AnimationController` repeating)
- Feedback háptico diferenciado: `HapticFeedback.lightImpact` al activar, `mediumImpact` al desactivar
- Estado "enviando": shimmer effect en el borde

### 2.5 — Status dots con pulso

Los dots de estado en `SensorCard`:
- Normal (verde): pulso lento cada 3s (`AnimationController` repeat, scale 1.0 → 1.3 → 1.0)
- Warning (amarillo): pulso más rápido cada 1.5s
- Critical (rojo): pulso rápido cada 0.8s + glow más intenso
- Offline (gris): sin pulso, opacidad reducida

### 2.6 — Tank level fill animado

`TankLevelCard` ya tiene `AnimatedContainer` — mejorar con:
- Ondulación en la superficie del agua (via `CustomPainter` + `sin()` wave)
- Gradiente vertical que se oscurece hacia abajo (simula profundidad)
- Cuando el nivel es crítico (<20%), el color parpadea suavemente

### 2.7 — Toggle switch con label animado

Para los switches de auto mode en settings:
- Al cambiar estado, el label hace un crossfade animado
- El thumb del switch tiene un micro-bounce al llegar al destino

## Fase 3: Transiciones de Navegación

### 3.1 — Shared Axis Transitions

**Nuevo: `AppPageRoute<T>` (reusable PageRouteBuilder)**
- Transición por defecto: Shared Axis (vertical) — el contenido nuevo sube mientras el viejo baja
- Duración: 400ms con `Curves.easeInOutCubic`
- Fallback a `MaterialPageRoute` behavior en devices lentos

**Aplicar en:**
- Settings hub → sub-screens (shared axis vertical)
- Dashboard → SchedulingScreen (shared axis horizontal)
- Login ↔ Registration (fade through)

### 3.2 — Bottom nav transitions

En `MainShell`, reemplazar `IndexedStack` con transiciones:
- Al cambiar tab: fade out rápido (150ms) + fade in del nuevo (300ms)
- Dirección del slide sigue al index (izquierda si tab < anterior, derecha si >)
- Mantener `KeepAlive` en los tabs para no perder estado

### 3.3 — Hero transitions para sensor cards

- Dashboard `SensorCard` → History chart detail (futuro)
- Tag por sensor key (`hero_ph`, `hero_temp`, etc.)
- Transición: la card se expande en la pantalla de detalle

## Fase 6: Detalles de Pulido

### 6.1 — Shimmer loading states

Reemplazar `CircularProgressIndicator` en estados de carga:
- `ShimmerPlaceholder` widget que muestra la forma del contenido futuro
- Dashboard: 3 sensor card skeletons + 2 pump button skeletons
- History: chart area skeleton + time range bar skeleton
- Settings: 4 tile skeletons

### 6.2 — Empty states ilustrados

Cuando no hay datos:
- Dashboard sin ESP32: ilustración de una planta + "Vincula tu dispositivo"
- History sin datos: ilustración de un gráfico vacío + "Aún no hay lecturas"
- Cada empty state tiene un CTA claro

### 6.3 — Snackbar → Toast notifications

Reemplazar snackbars por toasts flotantes al estilo de las referencias:
- Aparecen desde arriba (no desde abajo)
- Bordes redondeados (radius 16)
- Icono de estado (check verde, warning amarillo, error rojo)
- Auto-dismiss con progress bar sutil
- Slide-in + fade-out animations

### 6.4 — Haptic feedback system

Estandarizar vibraciones:
- `lightImpact`: cambios de estado (toggle, select)
- `mediumImpact`: acciones confirmadas (pump activada, profile guardado)
- `heavyImpact`: acciones destructivas (pump ácido/base)
- `selectionClick`: scroll por items, tab change

## Notas Técnicas

- **Performance:** Todas las animaciones deben usar `AnimationController` con `vsync` (no timers).
  Los `CustomPainter` para waves/pulses deben usar `shouldRepaint` eficientemente.
- **Accesibilidad:** `reduceMotion` check — si el usuario tiene animaciones reducidas en sistema,
  usar duraciones de 0ms (skip animations). `MediaQuery.of(context).disableAnimations`.
- **Testing:** Las animaciones no necesitan tests unitarios, pero los widgets con lógica
  (como `AnimatedValue` interpolation) sí.
